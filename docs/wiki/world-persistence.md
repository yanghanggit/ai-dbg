# 世界快照持久化（World Persistence）

世界快照持久化是开发期的状态留痕层：把一次运行点的 `WorldState` 连同各领域子状态，序列化为一棵明文目录树落盘，供开发者与 Agent 直接审阅、比对差异、判断运行状态。它是「人可读优先」的临时方案，不是最终存储——正式存储应落到数据库。用户会话历史不属于世界快照，独立持久化且不随游戏回滚。

## 设计意图

- **明文、可审阅**：各领域状态拆分为独立文件，目录结构即状态结构，可逐文件打开查看，也便于比对两个运行点的差异。
- **快照而非日志**：每份落盘都是一份完整、自足的状态切片，读取任意一份即可复位世界并继续推进，命令间不依赖进程内记忆。战斗、回合、行动槽与回合记录作为 ECS 实体，和角色、场景、副本一起随实体组件数据落盘，不再额外维护独立的战斗子状态文件。
- **世界与历史分离**：快照只承载可回滚的游戏状态；用户会话是 append-only 历史，单独存储，游戏重建或回滚都不影响它。读取快照后，会话按用户另行加载。
- **开发期专用**：不追求写入吞吐、增量更新或查询能力，这些交由未来的数据库承担。

## 与其他系统的关系

- 由唯一全局 pipeline 驱动：每次动作完成一个阶段后，产出一份新快照。
- 被 AI 操作 CLI 消费：读取某份快照还原世界后继续执行下一动作，形成「读快照 → 动作 → 写快照」的无状态循环。
  → 参见：[DBG AI 操作 CLI（ai-dbg-agent-game）](run-agent-game.md)
- 最近一次成功写盘会更新同目录下的指针，供 job 失败时恢复到进入执行前的世界。
  → 参见：[Job 执行与事件日志（Job Execution）](job-execution.md)
- 快照承载的世界模型属于核心模型层，其语义不在本系统定义；用户会话历史的语义见独立文档。
  → 参见：[用户会话历史（PlayerSession）](session-history.md)

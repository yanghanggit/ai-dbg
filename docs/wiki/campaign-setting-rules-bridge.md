# 战役设定与全局规则（CAMPAIGN_SETTING / SYSTEM_RULES）

## 分层

`CAMPAIGN_SETTING` 与 `SYSTEM_RULES` 都封存在 `demo/`，引擎不持有任何具体世界观：

- **战役设定**：只点明题材范围、基调与转译边界——架空奇幻、多文化并存、现实母题须改写为本世界独有的名目。它不写具体地点、国家、阵营、剧情走向或玩法循环。
- **全局规则**：纯机制契约——角色扮演、实体全名、根属性、战斗规则、扮演与事实、场景移动。它不写具体职业、英雄样本或故事秘密。
- **副本规则**：副本=遗迹/巢穴/秘境的语义单独成段，与全局规则拼接后注入实体；它不属于战役大背景。

两者随蓝图写入每个实体的 `system_message`，作为 agent 记忆的首条系统消息长期驻留。故事层内容变化只需改 `demo/` 并重刷蓝图，引擎代码不变。

## 设计取舍

- **抽象设定是惰性知识**：只写边界与点题，不铺陈范例；具体意象交给副本内容与角色自己的设定。
- **玩法流程不进公共设定**：接单、回城、养成等流程不属于每个实体都必须知道的公共知识；当前版本只保留副本内的卡牌战斗流程。
- **数量属输入数据，不属设定**：房间总数、怪物数这类结构常量由代码持有；当前版本使用预置副本文件，不再动态生成副本。

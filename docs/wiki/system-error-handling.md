# System 错误处理与回滚边界

## 结论

system 可以自行处理预期内的失败并正常返回，这样不会触发 pass 回滚。只有未被捕获的异常会中断 pass，并由上层把 ECS 与 agent 记忆恢复到运行前快照。

这个边界属于业务层：基础设施只负责「异常抛到边界就回滚」，不替 system 决定哪些失败可以恢复。

## 三种出口

- **自行处理并返回**：pass 继续，不回滚。适用于网络失败、模型输出不合法等预期内失败。
- **抛 `StopPipeline`**：正常提前结束，不回滚，剩余 system 被跳过。
- **抛其他异常**：中断 pass，上层回滚到运行前快照。

## 可以自行处理的条件

- 失败可预期、可恢复；
- 所有可能失败的解析与校验都在写 ECS 或记忆之前完成；
- 失败被记录（日志、领域事件或失败提示），不是静默忽略；
- 后续 system 不依赖这次结果。

只捕获已知失败类型，不要用宽泛捕获掩盖 bug。LLM 通讯层的预期网络失败通常以结果状态返回，而不是异常；system 应显式检查结果，而不是依赖抛出。

## 回滚粒度

快照按整次 pass 保存，回滚也是整次 pass，不是单个 system。某个 system 处理了失败并写入状态后，如果后续 system 抛出异常，整次 pass 仍会回滚，包括此前已处理的部分。

需要跨回滚保留的失败信息，应写入快照之外：job 事件、会话历史或日志。

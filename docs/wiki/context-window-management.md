# 上下文窗口管理（Context Window Management）

## 意图

角色与场景的 agent 记忆随回合单调累积，上行 prompt 持续膨胀，最终逼近模型上下文上限。系统用两种减量手段应对：写入时机就去痕（单次工具循环结束即替换成结论），以及按上下文占比触发的全局压缩。

## 提示词留痕

提示词与模型回包默认按原样写入记忆；单轮无工具的调用（如环境叙事）只留下「提示词 + 回包」两条。

怪物决策不留全文：`MonsterCombatDecisionSystem` 走工具循环，提示词与工具轨迹先如实进记忆，落库阶段整段变成一条人类可读的决策记录，原文只进 `replaced_messages`，不再上行。出牌结算已改为确定性计算，不产生 LLM 轨迹，因此不需要逐次压缩。

## 阈值触发压缩

`DeepSeekClient` 在每次响应后计算 token 用量占模型上下文窗口的比例，随 AI 回复消息同步到 `AgentMemory`，作为「该 agent 上下文有多满」的信号；经存档持久化、恢复时回填，跨命令可读。

`ContextCompactionSystem` 挂在每条流程管线的收尾前，每轮遍历所有 agent，对占比超过设定阈值的 agent 触发压缩：保留首条 system 消息，其余压成一条第一人称摘要，并把占比重置回 0，等待下一轮真实调用重新累计。

压缩只保留首条 system prompt，以及显式声明「压缩时保留」的消息。绝大多数事实型记录（胜负、战利品、领取、阵亡）只属叙事，允许被摘要吞掉——它们的权威载体是组件，记忆只负责让人记得大概发生过什么。

## 作用域

逐次去痕只作用于怪物决策这类角色侧工具循环；场景侧出牌结算已无 LLM。阈值压缩对所有 agent 一视同仁，是最后兜底手段。
